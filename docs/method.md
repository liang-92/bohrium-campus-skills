# 方法：把 PDF 还原成可引用的结构

这份文档写的是「为什么这样实现」，不是 API 说明。目标读者是想改它的人。

## 1. 为什么不用现成的 Markdown 转换

`pymupdf4llm`、`docling` 这类工具能直接吐 Markdown，效果也不差，但它们有两个问题：

1. **不可解释**：出现串栏时，你拿不到「哪一行被放到了哪一栏」的中间结果，没法定位。
2. **不可核验**：输出是连续文本，没有稳定的块 id，评审无法把一句结论映射回某页某块。

所以这里保留了块级中间表示：`p03-b012` 这样的 id 一旦生成，后续所有引用都用它。

## 2. 五个步骤

### 2.1 取字（多引擎兜底）

顺序：PyMuPDF → pdfplumber → pypdf → poppler `pdftotext`。

- 选「有效页数 × 字符量」得分最高的引擎；
- 混合文档（部分页是扫描件）里，空页再用其他引擎补一遍；
- 仍然空、但页面有图片的，渲染 220dpi 走 OCR，并在 `source.ocr_pages` 记录页号。

记录 `source.attempts`，评审能知道每个数字是怎么来的。

### 2.2 去页眉页脚

四类规则，命中即剔除并写入 `running_heads_removed`：

| 类型 | 判据 | 例子 |
|---|---|---|
| 页码 | 纯数字/罗马数字，位于上下 8.5% 边距 | `3`、`iv`、`Page 3 of 12` |
| 重复边距行 | 数字归一化后跨页重复 ≥30% | 期刊名 + 卷期 |
| 旋转文本 | 高远大于宽且高度 >25pt | arXiv 左侧竖排编号 |
| stamp | 已知模板 | `arXiv:1706.03762v7`、版权行、`Preprint` |

重复判断用归一化（数字→`#`）而不是精确匹配，否则页码变化会让「第 1 页的页眉」和
「第 2 页的页眉」被当成两行不同的文字。

### 2.3 阅读顺序：XY-cut

递归地对一个区域找「能把区域完整二分」的缝隙：

1. 竖直缝隙：把区域内所有行的 `[x0,x1]` 求并集，并集之间的空隙即候选；
2. 水平缝隙：同理，用 `[y0,y1]`；
3. 候选缝隙必须满足 `左侧行数 + 右侧行数 = 总行数`（没有行跨过它），否则作废；
4. 取较宽的缝隙切分，先竖后横，递归到无法再切。

为什么「完整二分」这个约束重要：在一张双栏页上，通栏的图注、跨栏表格会让「整页统一
的一条栏缝」不存在。要求完整二分后，算法会先按水平缝隙把页面切成「标题带 / 双栏带 /
通栏表带」，再在每个带内找栏缝——这正好对应人眼的读法。

单栏页面有一个专门保护：如果窄行（宽度 < 全文宽 72%）不到总行数的 40%，直接跳过栏检测。
否则插图旁边的空白会被误判成栏缝（`Attention` 论文第 3 页就是这种情况）。

### 2.4 段落重建

在栏内按阅读顺序合并行，断段条件是「任一成立」：

- 与上一行的垂直间距 > 中位行距 × 2 + 2pt；
- 上一行明显短于该栏右边界（`< 右边界 - max(10, 2.2×字号)`）——这是两端对齐文本里
  最可靠的段末信号；
- 字号变化超过 8% 或粗细变化；
- 当前块已经 12 行 / 1200 字符。

行末连字符 + 下一行小写时合并（`advanta-` + `geous` → `advantageous`），
但保留 `well-known` 这类真实连字符（下一行首字母大写或整词在词典中不成立时不动）。

### 2.5 结构标注

- **标题**：编号深度（`3.2.1` → 3 级）、字号比（≥1.45 一级 / ≥1.25 二级 / ≥1.10 三级）、
  常见名称（Abstract / Introduction / References…）；
- **被拆开的标题**：`3.1` 单独成块时与下一块合并（这类情况在双栏 PDF 里很常见，
  编号和标题用了不同字体）；
- **表格**：优先 `find_tables()` / `extract_tables()`，失败时用「一行里出现 ≥2 处宽间隙」
  的行组兜底；
- **公式**：数学符号密度 + 编号 `(12)` + `=` 关系式，同一公式的碎片行按垂直距离合并；
- **参考文献**：从 References 标题开始，优先按 `[n]` / `n.` 切分，无编号时按「含年份」
  判定新条目，续行并入上一条。

## 3. 证据模型

每个块产出：

```json
{"id": "p03-b005", "page": 3, "column": 0, "bbox": [72.0, 301.4, 290.1, 372.8],
 "section": "3 Model Architecture > 3.1 Encoder and Decoder Stacks",
 "type": "body", "text": "The encoder is composed of a stack of N = 6 identical layers."}
```

引用规则：

- `block` 必填，`page` 由块给出，不手写；
- `quote` 是原文子串（归一化空白后比对），`verify()` 会检查；
- 跨块引用写 `p03-b005+p03-b006`，表示这条结论由两块共同支撑。

## 4. 已知失败模式

| 现象 | 原因 | 现在的处理 |
|---|---|---|
| 表格被拆成两半 | 跨页续表没有合并 | 各页独立识别，题注相同则保留两条并标注 |
| 作者抽不全 | 姓名与单位在同一行、多栏并排 | 会尝试在单位关键词处切断；失败就不写，不猜 |
| 扫描页乱序 | OCR 只给文本行、没有坐标 | 按行输出，标记 `filled_by: ocr`，顺序置信度低 |
| 三栏以上 | 递归切分可以处理，但窄栏会触发单栏保护 | 记录 `columns`，异常时在 `coverage.issues` 说明 |
| 竖排/海报 | 不在设计范围内 | 结果会明显异常，`coverage` 里字符密度会暴露 |

## 5. 为什么这样能提升「使用增益」

对照基线（直接把 PDF 文本塞给模型）时，这里的增益来自三处可验证的差异：

1. **顺序正确率**：串栏会直接污染下游每一条结论；XY-cut 后 `block_page_inversions = 0`。
2. **可核验性**：每条输出都有锚点，评审能抽查；基线做不到。
3. **稳定性**：同一案例三次运行结果一致（`docs/benchmark.md` 的 fingerprint），
   评测的方差来自模型，而不是解析。

这三点都能用 `bench/run_bench.py` 和我附的样例复现，不靠文字自述。
