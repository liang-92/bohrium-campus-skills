## 4. 共性硬伤（一改，十题一起涨）

### P0-1 异常输入直接崩，且**不写 result.json**

实测 4 种输入，全部 `rc=1`、没有 `result.json`：

| 输入 | 现象 |
|---|---|
| `/input` 不存在 | `AttributeError: 'NoneType' object has no attribute 'get'`（`core/run.py:89`） |
| 目录里只有 `notes.md`、没有 PDF | 同上 |
| AES-256 加密 PDF | `RuntimeError: no PDF engine produced text`（`backends.py:313`） |
| 0 页 PDF | 同上 |

只有“扫描件无文字层”这一种走到了 `status: partial`（blocks=0）。

**为什么致命**：赛题要求“运行失败要说明、部分结果要标边界”。崩溃 = 该案例零产物 = 完成度/可核验性一起归零，而且三个案例是算术平均，一崩就掉一大截。

**怎么修**（约 40 行）：
1. `main()` 外层包 `try/except BaseException`，`finally` 里若没写成 `result.json` 就补一份：
   `{case_id, status:"unable", reason, evidence:[], uncertainty:{missing:[...]}, provenance:{engine, attempts}}`。
2. 把 `doc.get("document", {})` 改成 `(doc.get("document") or {})`（同类写法全查一遍）。
3. 引擎全部失败时区分原因：`encrypted` / `no_pdf` / `zero_pages` / `corrupt`，写进 `reason` 与 `run.log`。

### P0-2 表格：引擎给了表，但行列是塌的

同一份 Attention：

| 表 | 实际 | 抽取结果 | 问题 |
|---|---|---|---|
| Table 1 | 表头 + 4 种层 = 5 行 | **2 行 × 4 列** | 4 行被并成 1 行；`Self-Attention / Recurrent / Convolutional / restricted` 挤在一个单元格 |
| Table 3 | 8 行 × 多列 | 8 行 × **3 列** | 列被并；`0.1` 变成 `01`，小数点丢失；`PPL(dev)`/`BLEU(dev)` 混在一起 |

`source: engine` 说明走的是 `find_tables()`；**无框线表格**下它按文本对齐猜行，行一塌，后面的 `normalize_table` 只会补空列，不会纠错。

另外 p9 的表格单元格会被当成正文块（`col 0..5` 来回跳 4 次），阅读顺序在表格页被打散 —— 这正是赛题“拆得清”要考的点。

**怎么修**：
1. 引擎结果做**质量门**：行数 < 列数、任一单元格含 3 个以上换行拼接值、或单行字符数超过中位数 3 倍 → 判为塌陷，改用 `detect_tables_from_lines` + 自建行列聚类。
2. 用 cell bbox 的 y 中心聚类重建行、x 中心聚类重建列（`find_tables` 的 `cells` 带 bbox，比 `extract()` 可靠）。
3. 解析阶段把表格区域内的块标 `type="table-cell"` 并从 `doc.md` 正文流里剔除，只在 `content.tables` 出现一次。
4. 小数丢失单独查：`normalize_table` 里对 `\d` 与 `.` 的处理，别在清洗时把点吃掉。

### P0-3 公式：7 条里只有 3 条是真的，且没有 LaTeX

- 真公式：(1)(2)(3)。
- 假阳性：`i=1 qiki, has mean 0 and variance dk.`、`∈Rdmodel×dk, W K ∈...`、`and W O ∈Rhdv×dmodel.`（正文碎片）。
- 第 3 条被截断：`lrate = d−0.5 model · min(step_num−0.5, step_num · warmup_st`。
- **没有任何 `tex`/`latex` 字段**，`build_latex` 直接把这段 Unicode 塞进 `equation` 环境 → `pdflatex` 必报 `Unicode character` 错。

这同时打两个题：parse（公式保真）和 latex（可编译）。

**怎么修**：
1. 公式块加 `tex` 字段：至少做上下标（`_`/`^`）、希腊字母映射、`\frac`、`\sqrt`、`\sum` 的规则化转换；转不动的原样保留并标 `tex_confidence: low`。
2. 编号识别只在行尾 `(n)` 且该行符号密度达标时成立，避免正文碎片混入。
3. `build_latex` 对公式做 `if tex else verbatim`，并在导言区按需加 `amsmath`/`amssymb`。

### P0-4 引擎降级是“静默”的

只有 pypdf 时：**78 块 / 0 表 / 0 公式 / 0 参考文献**，而 `status` 仍是 `complete`，`validate.ok: true`。
SKILL.md 写的是“缺什么会在 run.log 和 coverage.json 里写明，不会静默降级”，实际只写了 `issues: no tables detected`，没写“引擎能力不足”。

评测镜像如果不带 PyMuPDF（`resources.yaml` 把 pymupdf 标成 optional），六个题会一起掉到 78 块的水平。

**怎么修**：
1. `resources.yaml` 把 `pymupdf` 移到 `required`，写明安装方式与版本上限（`>=1.23,<3`）。
2. `quality` 增加 `engine_tier: layout|text-only`；text-only 时强制 `status: partial` + `uncertainty` 明写“无版面引擎，块粒度退化为整页，表格/公式不可用”。
3. 页数 > 0 但块数 < 页数 × 5 时，视为异常粒度并告警。

### P0-5 十份“示意输出”是同一个空壳

`skills/*/examples/result.example.json` 的 md5 全部相同，主字段 `document: null`，只标注“接口示意”。
赛题明确要“至少一组输入、调用方式和示意输出”，评审看到 10 个一模一样的空模板，生态贡献的“文档完整性”拿不满。

**怎么修**：每个 skill 生成一份**真实小样例**（用一篇 1–2 页的 CC0 论文或自造两段文本），保留 2–3 个真字段 + 1 条 evidence，文件头注明“示例，非正式案例结果”。成本约 1 小时，10 题各 +1 分。

### P0-6 文档与实现有 5 处对不上（评审一核就扣分）

| 文档说 | 实际 |
|---|---|
| `content.blocks` 带 bbox（SKILL.md 输出表） | `result.json` 的块只有 id/page/column/section/type/text，**bbox 只存在于 doc.json** |
| 扫描件“自动 OCR” | 无 tesseract 时只写“2 pages without text layer”，不说 OCR 失败原因，也不给替代路径 |
| LaTeX“编译两次” | 只跑一次 |
| `files` 含 `main.tex`、`latex/main.tex` | 只返回 `["main.tex"]`（磁盘上确有 `latex/main.tex`） |
| “不会静默降级” | pypdf-only 仍 `complete`（见 P0-4） |

**怎么修**：要么改代码对齐文档（推荐 bbox、files 两项，成本低），要么把文档改成实际行为；不要留模糊地带。

### P0-7 描述只有英文，中文赛题有触发风险

10 个 `description` 全是英文（270–315 字符），而 `task.md`、案例说明都是中文。
Skill 是靠 description 被选中的，中文任务下匹配度天然吃亏。

**怎么修**：在 description 末尾追加一句中文触发语（不超 512 字符），例如
`也用于中文任务：文献解析、双栏串栏、跨页表格、公式提取、扫描件识别。`
十个 skill 各改一行，收益是“能不能被正确加载”，属于性价比最高的一项。

## 5. 逐题建议

> 每题的“现状”都来自实跑产物；“动作”按投入产出排序，前两条建议在提交前完成。

### 5.1 paper-parse（74）—— 底板，优先修
- 现状：268 块 / 27 章节 / 4 表 / 41 参考文献；6-gram 覆盖 94.3%，最低页 83%（p9 表格页）。
- 扣分：作者只抽到 2/8（`Llion Jones`、`Noam Shazeer`，连拼写都错）；表格塌行；公式 3/7；异常崩溃；块无 bbox。
- 动作：① 先修 P0-1（崩溃）；② 作者/单位用首页块的行聚类 + 上标符号切分，抽不全就标 `authors_uncertain`；③ 表格质量门 + 行重建（P0-2）；④ 块补 bbox。

### 5.2 paper-translate（66）—— 预算内做不完，最需要改流程
- 现状：Attention 262 段 / ACL 171 段，平均每段 145 字；`translation` 全空是设计。
- 扣分：按“一次一段”的写法，64 次请求只能译 24%，剩下 76% 空白；而且参考文献、表头、公式块也被切成了段。
- 动作：① 切段过滤：跳过参考文献条目、表格单元格、公式块、running head（能砍掉 40%）；② 合并 <120 字的相邻段，目标 ≤80 段；③ SKILL.md 写死“每次请求译 15–20 段，用 `apply_translations.py` 回填”，并给一个 `segments_batch(0,20)` 的示例命令；④ `verify --kind translate` 已有，补一条“未译段数 ≤5%”才算过。

### 5.3 paper-kg（61）—— 边太少，图谱不成立
- 现状：51 节点 / **3 条边**；节点里有 `Abstract` 这种非实体；一条 `improves` 边的证据引文是 `would increase the`（不支撑关系）。
- 扣分：知识图谱题的核心就是关系，3 条边基本等于没做；`status` 仍然 `complete`。
- 动作：① 关系抽取扩到“动词短语 + 实体对共现”：`X uses Y`、`X outperforms Y`、`X trained on Y`、`X evaluated on Y`、`X improves Y`；② 每条边必须带能支撑它的完整句（≥40 字），否则丢弃；③ 质量门：`edges < max(10, nodes*0.4)` → `partial`；④ 过滤章节名/“Abstract”等结构性词作为节点。

### 5.4 paper-intro（62）—— 只有证据，没有引言
- 现状：1 条问题句 / 3 条 gap / 3 条贡献 / 4 组相关工作；`uncertainty` 里写“prose is written by the agent”，但 SKILL.md 没让 Agent 写，产物里也没有 `draft` 字段。
- 扣分：题目叫“引言与相关工作写作”，评审要看的是能读的段落。
- 动作：① 产物增加 `draft: {paragraphs: [{role, text, citations[], evidence[]}]}`，5 段式；② SKILL.md 增加一步“按 outline 写 5 段，每段 ≥120 词，引用用 [n] 且 n 必须来自 entries”；③ 写完跑 `verify --kind intro`：段落数、引用命中率、每段是否有 evidence。

### 5.5 paper-methods（72）—— 参数多而杂，缺成段描述
- 现状：60 个参数、2 个数据集、5 条硬件、8 条复现清单；参数里混进了“attention heads 在表 3 的取值”等非设置项。
- 动作：① 参数按“训练/模型/数据/评价”四类归档，重复项合并；② 增加 `draft.methods`（3–4 段：数据、模型、训练、评价）；③ `missing` 字段列出“论文未报告的项”（seed、硬件型号等），这是加分项不是减分项，要在 SKILL.md 里强调。

### 5.6 paper-refs（70）—— 格式不达标
- 现状：41 条 entries / 40 个正文引用键 / 4 类问题（缺条目、未引用、重复、编号断档）都检出了。
- 扣分：`gbt()` 输出是 `作者. 题名[J]. 年. DOI:x`，缺刊名、卷期、页码；`parse_ref_entry` 根本没抽这些字段。
- 动作：① 解析补 `venue/volume/issue/pages/type`；② GB/T 7714-2015 与 APA 7 按类型分支（[J]/[C]/[M]/[EB/OL]）；③ 输出一份 `references.bib`（`@article{key, ...}`），可直接被 LaTeX 用；④ 数字编号与 `\bibitem` 对齐检查。

### 5.7 paper-notes（70）—— 自动卡片需要“人复核”这一步
- 现状：卡片 10 个字段、26 条分节笔记、16 条知识点、30 个术语；`status: complete`。
- 扣分：findings/methods 全是正则命中的句子，容易把 related work 里的“we find”当成自己的结论；没有让 Agent 复核。
- 动作：① SKILL.md 增加“逐条核对卡片，删掉非本文结论，补 1 句自己的话”；② 每条 bullet 强制带 `block`（已有）与 `section` 一致性检查；③ `status` 改为“findings ≥5 且全部有 block 才 complete”。

### 5.8 paper-nanopub（74）—— 方向对，数量少
- 现状：9 条断言，带 provenance 与 quality；结构最接近标准纳米出版物。
- 动作：① 断言按“主张类型”补齐（ empirical/method/comparative/causal 已有词典，但只出了 9 条），目标 20–30 条；② 每条断言给 `minimal_quote`（≤200 字）与 `support_level`；③ 增加 `nanopub.trig` 导出，评审可直接看 RDF。

### 5.9 paper-polish（67）—— 诊断有了，改写要落地
- 现状：65 条句级问题、术语一致性 1 条、guardrails 4 条；`partial` 正确（等 Agent 改）。
- 扣分：65 条对一次会话太多；没有“改完的版本”，评审看不到效果。
- 动作：① 按任务范围截断（摘要+引言，或 top 20 条），SKILL.md 写明“默认只改前 20 条”；② 产物增加 `revised_text`（段落级，保留原文对照）；③ `verify --kind polish` 检查数字/引用/否定词是否被改掉。

### 5.10 paper-latex（59）—— 编不过等于没交付
- 现状：`compile: {attempted: false}`（本机无 TeX），`tex` 在 payload 里截断到 20000 字符，公式是 Unicode，`files` 只有 `main.tex`。
- 动作：① 公式转 LaTeX（P0-3），否则有引擎也编不过；② 无引擎时至少做**静态自检**：环境配对、花括号平衡、`\cite` 与 `\bibitem` 对齐，写进 `compile.static_check`；③ `files` 返回真实相对路径列表；④ 若评测镜像可能无 TeX，补一条“交付 `main.tex` + `README.build.md`（TeX Live 安装/编译命令）”，并把 `status` 说明写清楚。

| P0 | KG 关系抽取 + 质量门 | 1 | +8~12 | 3 h |
| P0 | 引言/方法补 `draft` 正文 | 2 | +6~8/题 | 2 h |
| P1 | 作者/单位抽取 | 4 | +1~2/题 | 1.5 h |
